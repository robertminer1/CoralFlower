# CoralFlower 0.7.1-midi-rc1 — TRS MIDI Keys latency release candidate

**Release candidate, not yet published.** This is a focused MIDI performance update on top of CoralFlower 0.7.1. The existing reverb/delay MIX and FX bypass behavior is unchanged and will be addressed separately.

## Improved MIDI responsiveness

- FM-1 Keys incoming MIDI notes on the **HOME screen** now trigger the chord engine in the audio processing interrupt rather than waiting for a main-loop/UI round trip.
- The UI still mirrors the virtual-key state. Duplicate audio events are suppressed.
- Physical/MIDI key overlap, multiple MIDI notes folded onto the same FM-1 key, and MIDI input-mode/channel transitions have dedicated handling.
- Other screens and Direct/Roots MIDI modes retain the established behavior.
- TRS UART servicing inside an audio render was also improved so it need not await completion of the current audio render.
- Experimental MIDI latency measurement probes have been removed from this release build.

## Measured improvement

From an EP-133 KO II into an M-VAVE FM-1 over TRS MIDI, with FM-1 Keys mode:

| Timing measurement | Earlier firmware | Optimized diagnostic firmware |
| --- | ---: | ---: |
| UART packet complete → chord engine | 10.939 ms | 1.124 ms |
| UART packet complete → scheduled DMA audio | 13.838 ms | 3.775 ms |
| Maximum scheduled output in respective run | 16.327 ms | 5.330 ms |

The latest output timing fell by **about 73%** in these two runs. These measurements estimate scheduled digital output; they do not include the transmitting device's scheduling or measure the analog jack. The user reported noticeably tighter playback and successful tests of rapid sequences, key overlaps and screen transitions.

## Upgrade and fallback

Build from `feature/midi-low-latency` with `./build.sh --release 0.7.1-midi-rc1`. Install the resulting `.fwsc` file using the CoralFlower browser installer. Back up settings and keep a known-working firmware package available. The compile option `CF_MIDI_KEYS_FAST` in `firmware/src/coralflower.c` may be set to 0 to disable the optimized HOME-screen Keys path.

**Known separate issue:** Users report that disabling reverb or delay may reduce volume persistently and the MIX controls may function as volume boosters. This behavior predates the MIDI performance change and is **not fixed** in this candidate. See `docs/MIDI-KEYS-FAST-PATH.md` for technical details and qualification steps.
